# Greg Style Primitives

This file separates **portable Greg primitives** from any single page template.

## 1. Copy tone
- Lead with a sharp product thesis, not a category label.
- Pair aspiration with proof in the first screen.
- Prefer short, declarative sentences over feature sludge.
- Use concrete scale claims and operational language.
- Make every tagline feel shippable, not theatrical.

## 2. Section rhythm
- Alternate between dense proof and breathable explanation.
- Use short monospace kickers to reset context: `// the model`, `// the mesh`, `// in production`.
- Follow a repeatable cadence:
  1. orientation
  2. claim
  3. proof
  4. mechanism
  5. CTA

## 3. Metrics blocks
- Show 3-4 large numbers with units.
- Use metrics as evidence, not decoration.
- Favor numbers that imply operations, reach, latency, or throughput.
- Big stats should be scannable in under two seconds.

## 4. Code-window primitive
- Use a distinct chrome bar, filename label, and copy affordance.
- Keep the snippet short enough to parse immediately.
- Prefer realistic API calls or configuration fragments.
- The snippet should reinforce credibility, not just fill space.

## 5. Visual anchor primitive
- Include one dominant interactive or diagrammatic object per major surface.
- For infrastructure or network stories, favor canvas, SVG, rings, glows, HUDs, and topology hints.
- For docs and dashboards, the anchor can be a structured control surface instead of a hero globe.
- Decorative layers should support hierarchy, not obscure it.

## 6. Navigation + CTA primitive
- Minimal sticky navigation.
- One high-contrast primary CTA.
- Secondary CTA should deepen understanding, not compete.
- Nav labels should be terse and concrete.

## 7. Feature card primitive
- Use geometric symbols or subtle system icons.
- Each card needs one crisp claim and one technical qualifier tag.
- Avoid generic “easy / powerful / seamless” phrasing.

## 8. Dashboard translation
- Preserve Greg tone, but compress it into status surfaces.
- Use topology, incidents, timelines, counters, and operator notes.
- Add proof-of-life elements: status dots, deltas, sparklines, event streams.

## 9. Docs translation
- Keep the hierarchy crisp and practical.
- Show quickstarts early.
- Treat information scent like a design problem: clear labels, command blocks, structured pathways.

## 10. Framework translation
- Preserve rhythm and polish when moving from single-file HTML to TSX or other component output.
- Separate layout primitives from copy primitives.
- Keep the same density of proof, not just the same colors.
